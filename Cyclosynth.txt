Generator
---------
Added main/qs_build_lut_v.cpp, using qs_build_lut.cpp as the CLI/sampling
reference. It invokes the native Rust example qs_rz_bridge via one persistent
child process and pipes, avoiding shell command interpretation. The bridge
calls Synthesizer::new(epsilon, true).synthesize_rz(Angle::Rad(angle)).
V = sqrt(T) = diag(1, exp(i*pi/8)); V is not the unrelated sqrt(X) gate.
Upstream README defines ABC as matrix product A*B*C, so C acts first on a
column ket (its SynthResult field comment contradicts the README). The bridge
reverses the upstream string to chronological order: for stored ABC, A is
applied first, then B, then C, yielding matrix C*B*A. This stored order matches
the Instruction sequence convention; a future reader must follow it.
Upstream Q/q becomes V/v; T/t expands to VV/vv. Lowercase s/v denotes the
adjoint of S/V. Exact Clifford gates H, X, Y, Z, S, s remain unchanged.
Verified distances use cyclosynth's normalized diamond-distance convention
(half the usual channel diamond norm). Global phase is ignored.

Build the C++ executable independently of the legacy GMP-based LUT target:
  cmake -S . -B build-v-lut -DCMAKE_BUILD_TYPE=Release \
      -DCOMPILE_V_LUT_BUILDER=ON -DCOMPILE_LUT_BUILDER=OFF
  cmake --build build-v-lut --target qs_build_lut_v
COMPILE_LUT_BUILDER=ON also enables the new target. CYCLOSYNTH_BRIDGE is a
CMake cache FILEPATH override for the separately built native Rust bridge.

CLI (documented here only; the generator was NOT executed):
  qs_build_lut_v lower-bound upper-bound count output \
      [-t|--threads N] [-e|--epsilon E] [--backend PATH]
Bounds are radians, ordered, finite, and may not cross zero. count must be
positive. Samples use lower + (upper-lower)*i/count (upper excluded for a
nondegenerate interval), then are sorted by increasing absolute angle.
Negative intervals retain their signs. Zero is handled as an exact identity.
The default epsilon follows the reference angle-dependent decimal precision
(ceil(-log10(abs(angle)))+5), bounded to [1e-48, 1e-5]; zero uses 1e-5.
The explicit epsilon override accepts [1e-48, 1). --threads controls the
backend's Rayon worker count (default 8); angles are submitted sequentially.
Upstream searches may be expensive at tight epsilon and can fail to find a
circuit. On backend/I/O failure the partial temporary file is removed; a
completed output replaces the destination only after successful child exit.

Versioned V LUT format
----------------------
This is a standalone format. The existing Quicksilver LUT reader accepts
Instruction::Type bytes, and that enum has no V/VDG. It cannot consume these
files. No existing instruction values were repurposed, and no simulator or
compiler consumer was modified. A future consumer must explicitly parse
this format and support V/VDG before using it in the compiler/simulator.

All numbers are little endian; doubles are IEEE-754 binary64.
Header:
  8 bytes: ASCII QSVLUT1 followed by NUL
  uint64: number of entries
Each entry:
  float64: signed angle in radians
  float64: requested epsilon
  float64: verified normalized diamond distance
  uint32: gate-string byte length
  length bytes: ASCII gates in {H, X, Y, Z, S, s, V, v}, application order
Identity has length zero. There is no trailing terminator per sequence.
Readers should validate magic, count, lengths, alphabet, finite angles and
distances, and 0 <= distance < epsilon. This format intentionally differs
from the legacy double/uint16/Instruction::Type layout.
